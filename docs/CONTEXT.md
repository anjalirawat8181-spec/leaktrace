# LeakTrace: handover context

Generated by reading the code (read-only). Spec: `docs/prompt-app.md` (the task named it `PROMPT-APP.md`; the file is lowercase and the spec's repo tree lists the wrong name). Nothing was installed or run: `node_modules` is absent, so tests and build were **not executed** (section 15).

## 1. Summary
LeakTrace makes every printed copy of an exam paper textually unique (synonyms, optional commas, number style, MCQ option order, question order inside a block). Each copy carries a secret "fingerprint vector". A controller writes a template in a small DSL, generates up to 20 PDFs (one merged PDF per room), schedules release and close, and superintendents download their own centre's PDFs inside a time window. When a paper leaks, the controller pastes some text into the Trace Lab and the app names copy, centre, room, seat, invigilator and who downloaded the bundle. All six spec milestones (M1 to M6) are implemented in 3 commits; the working tree is clean. It is local-only: every external service sits behind an adapter with a local implementation, and **no AWS implementation or stub exists** (`createAdapters('aws')` throws). No Dockerfile, CI or deploy config exists.

## 8. Fingerprint engine (`packages/fingerprint/src/index.ts`)
**DSL:** `{{a|b|c}}` phrase point; `{{,|}}` an empty alternative makes it OPTIONAL; all-numeric/number-word alternatives make it NUMBER; `::options ... ::end` with `(A) ...` lines (OPTION_ORDER); `::shuffle ... ::end` containing numbered questions (QUESTION_ORDER). Ids `P1..Pn` in document order. Duplicate alternatives after normalisation are rejected. Context for each point = up to 25 chars of fixed text either side, cut at the neighbouring point (`leftCtx`/`rightCtx`).

**Vectors:** `choice_i = uint32be(HMAC_SHA256(key, "<examId>:<serial>:<attempt>:<i>")) mod k_i`; k = number of alternatives, or n! for order blocks. Re-roll (attempt++ up to 100,000) until Hamming distance to all earlier vectors >= 4. Capacity = sum(log2 k); required = log2(copies) + 12; generation fails with 422 if short. Vectors are stored in `copies.choice_vector`.

**Detection (`detectLeak`):** normalise (NFKC, lowercase, unify quotes/dashes, collapse whitespace). For each simple point: exact match of context+alternative probe, else exact match of the alternative alone, else fuzzy match (Levenshtein similarity >= 0.9); exactly one winner (top two must differ by >= 0.02 similarity) = observed, otherwise unknown. Order blocks: locate each option/question and read the order. Score each copy `matches - 3 x mismatches`, sort by score, mismatches, matches, serial. Top 5 returned.

**Verdicts:** IDENTIFIED if not a single line, observed >= log2(N)+2, top mismatches <= 1, top matches >= log2(N)+4, and runner-up has >= 3 more mismatches. POSSIBLE if enough evidence but not identified; INSUFFICIENT if observed < log2(N)+2 or the text is a single non-empty line. Coincidence: p = product of 1/k over observed points; expected false matches = (N-1) p; `oneIn = 1/that`. The API maps trace status POSSIBLE/INSUFFICIENT to case status INCONCLUSIVE.

**Differences from spec:** (1) extra "single line" rule forces INSUFFICIENT (spec only counts points). (2) Probe merging when a context is under 6 chars is not visibly implemented (grep found no 6-char rule; unclear). (3) Extra exact-match shortcuts before fuzzy search. (4) `generateVectors` hard-codes `totalCopies <= 20` (index.ts ~line 395) regardless of `MAX_COPIES_PER_EXAM`. (5) `visible_code` = first 6 hex of SHA-256(`serial + FINGERPRINT_KEY`) as in spec.

## 16. Risks for the AWS phase
1. **No AWS code at all.** All seven interfaces need implementations; `createAdapters('local')` is hard-coded in two files (api `adapters.ts:7`, worker `main.ts:9`) and the factory requires a Postgres Pool.
2. **Shared filesystem assumption:** API and worker share `./data`; local-file PUT/GET live in the API. In AWS the worker cannot see API disk, so S3 is mandatory for papers and evidence.
3. **Signed URLs are relative paths** (`/api/local-files/...`) and the local GET always replies `application/pdf` and `inline`. S3 presigned URLs are absolute and cross-origin: bucket CORS for browser PUT (evidence) and a CSP check (helmet defaults are on) are needed.
4. **Postgres as queue/scheduler/heartbeat:** worker and API both need DB connectivity; moving to SQS/EventBridge changes at-least-once and DLQ semantics (DLQ move is lazy in local; SQS uses redrive policy; local `depth` counts in-flight messages too).
5. **Scheduler:** release/close fire only while the API process runs; `cancel` is never used (rescheduling relies on upsert by name); EventBridge Scheduler needs a target (queue ARN) and role. Timezone is hard-coded `Asia/Kolkata` (`apps/api/src/time.ts`).
6. **Worker failure handling:** failures are only logged; `failed` never incremented; DLQ has no consumer; exam stays GENERATING. A message that is slower than the 30 s visibility timeout would be redelivered (`createAdapters` visibilitySec default 30).
7. **Secrets:** FINGERPRINT_KEY, JWT_SECRET, LOCAL_FILES_SECRET come from `.env`; no secrets-manager path. Worker is forced to hold FINGERPRINT_KEY and JWT_SECRET by `REQUIRED_CONFIG_KEYS` though it uses neither.
8. **Auth/proxy:** login rate limit and session are per-process (in-memory limiter breaks with >1 API instance); `TRUST_PROXY` is boolean (trusts all hops); cookie `secure` only when `NODE_ENV=production`; SameSite=Strict needs web and API on one origin (no CORS, `WEB_ORIGIN` unused), so use one CloudFront/ALB host with `/api` routing.
9. **Run model:** api/worker start via `tsx` with `--env-file=../../.env`; no compiled build, no Dockerfile, no health probe for the worker, no CI. The seed imports `@leaktrace/fingerprint/dist/seed-paper` so packages must be built first.
10. **Single-instance API duties:** the poller and consumer run inside the web API process; scaling the API duplicates them (safe because of SKIP LOCKED, but wasteful).
11. **Hard-coded localhost values:** Postgres URL with port 5434 in `.env.example`, `db/setup-test-db.mjs`, `scripts/screenshots.mjs`, vitest configs; `apps/web/vite.config.ts` proxy default `http://localhost:4000`; `docker-compose.yml` credentials `leaktrace/leaktrace`.
12. **Quirks:** global room-seat cap, `demo-set` and detection run synchronously in the API; `/trace/cases/:id` re-runs analysis each time; `GET /exams/:id/spot-the-difference` regenerates vectors from the key (rotating FINGERPRINT_KEY would break trace and spot-diff for existing exams); no purge of local tables; Config adapter unused.
