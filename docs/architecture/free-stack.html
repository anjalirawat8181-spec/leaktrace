LeakTrace on the free stack

The public demo runs on free tiers only. The same code runs here as on AWS; APP_MODE=cloud swaps the adapters behind packages/adapters, and the queue and scheduler live in Postgres.

Vercel · Render (Singapore) · Neon · Cloudflare R2
Client Static hosting Compute Database Object storage Automation

Main flows

  1. Generate: the controller clicks Generate, the API saves 20 copies in Neon and queues one job per room, the in-process worker renders and merges each room's PDFs and puts them in R2. About 28 seconds for 20 copies.
  2. Release and download: the schedule is a row in Neon; the API's poller fires it, marks the exam released, and a superintendent downloads through a 120 second signed R2 link.
  3. Leak trace: leaked text is compared with every stored fingerprint, with typo tolerance, and names the copy, centre, room, seat and invigilator.
  4. Nightly reset: a workflow calls reset-demo, which wipes the demo data and R2 files and seeds a fresh dataset.

Limits that shape the design

  1. Render Free sleeps after 15 minutes without traffic, so a keep-warm ping runs during the day.
  2. Neon has a monthly compute allowance, so the queue and scheduler stop polling when nobody is using the site.
  3. One small process does everything, so the demo caps exams, paper length and photo size.
  4. No authenticated hop between Vercel and Render, so limits have a per-address and a global tier.
