01-config-loader.png: Loads every parameter under /leaktrace/prod from SSM Parameter Store at startup, decrypting SecureStrings and keying each value by its last path segment. It replaces the .env file in AWS mode so no secrets live on the instance or in code.
02-s3-adapter.png: Implements the existing Storage interface on Amazon S3: upload, download, existence check and short-lived presigned download links. Generated papers and evidence photos move from the local disk to a bucket that both the API and the worker can reach.
03-sqs-adapter.png: Implements the Queue interface on Amazon SQS, long-polling up to 20 seconds and reporting how often a message was received. Failed messages are not deleted, so the queue's redrive policy moves them to the dead-letter queue.
04-sns-adapter.png: Implements the Notifier interface on Amazon SNS, sending leak, ops and release alerts to their own topics. This replaces the local notifications table so alerts can reach email subscribers.
05-scheduler-adapter.png: Implements the Scheduler interface on EventBridge Scheduler, creating one-time release and close schedules in Asia/Kolkata time that deliver to the exam-events queue. Re-scheduling updates the existing schedule instead of failing.
06-db-ssl.png: Builds the PostgreSQL connection for RDS from the SSM parameters with SSL turned on. RDS is reached over the network in AWS, so the connection must be encrypted.
07-build-scripts.png: Adds build scripts that compile the API and worker with tsc into dist/, a separate tsconfig for that build, and the root npm run package command. The EC2 instances run plain node on compiled JavaScript instead of tsx.
08-package-script.png: Stages each app with its compiled code and only its production dependencies, then creates a tarball that unpacks straight into /opt/leaktrace/<app>. It also checks that each archive contains its entry file.
09-migrate-entry.png: A standalone migration entry point that creates the database schema only when it is missing, inside one transaction. It is safe to run on every service start, which is how the API instance uses it.
10-seed-entry.png: A standalone, idempotent seed entry point for the demo users, centres, rooms and exam. It reads the database settings from SSM in AWS mode or from DATABASE_URL locally.
11-health-port80.png: The health check now answers {"status":"ok"} for the load balancer or monitoring, and the API listens on port 80 in AWS mode after loading SSM settings. Local mode keeps its old startup path.
12-user-data-api.png: First-boot script for the API instance: installs Node.js 20 and the PostgreSQL client, creates the leaktrace user, and fetches and unpacks api.tar.gz from the ccl2026 deploy bucket.
13-user-data-worker.png: The same first-boot steps for the worker instances in the Auto Scaling group, using worker.tar.gz and /opt/leaktrace/worker.
14-systemd-unit.png: The systemd unit that runs the API as the unprivileged leaktrace user, migrates before each start, binds port 80 through CAP_NET_BIND_SERVICE and restarts until the database is ready. The worker unit is the same without the port capability.
